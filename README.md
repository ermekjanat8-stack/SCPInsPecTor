# CSP Inspector — тема 6

Запуск: START.cmd. Требуется Node.js 20 или новее. Откройте http://127.0.0.1:8787. Без установки зависимостей и API-ключей.

## Выполненные пункты задания

- Конструктор default-src, script-src, style-src, img-src, connect-src, frame-ancestors.
- Переключатели self, none, unsafe-inline и *, включение/выключение директив. unsafe-inline недоступен там, где неприменим. none исключает другие источники.
- Свои домены: добавление, удаление, проверка ввода и дубликатов.
- Готовый HTTP-заголовок с копированием, отдельный meta-тег.
- Немедленное объяснение разрешений и автоматический аудит при каждом изменении.
- Предупреждения об unsafe-inline, широком default-src, отсутствии frame-ancestors/default-src и дополнительные проверки предыдущей версии.
- Три профиля загружаются из profiles.json: строгий, аналитика, плохой пример. Домен analytics.example.com — учебная заглушка.
- Локальная демонстрация с настоящим meta CSP и реальными сообщениями браузера в Console. Текущая политика передаётся на /demo. Наблюдатель и CSS загружены до meta, проверяемые ресурсы — после.
- Проверка собственного приложения, разбор текста, Report-Only и выгрузка JSON.
- По последнему запросу добавлена проверка своего публичного сайта по URL: GET заголовков, до пяти перенаправлений, обычный аудит и ML для каждой полученной политики. Домены конструктора по-прежнему не загружаются.

## Демонстрация для защиты

1. Выберите «Строгий». Откройте «Проверить в браузере»: встроенный скрипт блокируется, локальная картинка разрешена.
2. В конструкторе включите img-src 'none'. Откройте демонстрацию снова: картинка также заблокирована. F12 → Console показывает сообщения браузера.
3. Выберите «Плохой пример»: аудит показывает риски, а в демонстрации скрипт выполняется и картинка загружается.
4. Выключите default-src: появляется соответствующее предупреждение. Выключите frame-ancestors: показано отсутствие ограничения на встраивание со стороны CSP.
5. Добавьте домен в script-src, скопируйте заголовок, скачайте JSON.

Важно: default-src * не отменяет явные директивы и не разрешает inline автоматически. frame-ancestors не наследует default-src и не поддерживается в meta; для него нужен HTTP-заголовок. В копируемом meta он исключён. В демонстрации полная политика оставлена для наглядного сообщения браузера о неподдерживаемой директиве.

Строгий профиль — учебная исходная конфигурация, не универсальная гарантия безопасности. Анализатор не доказывает XSS, не проверяет обходы доверенных доменов или исходный код приложения. Расширенный аудит может рекомендовать дополнительные base-uri/form-action вне шести директив задания.

Тесты: node --test. Спецификация: https://www.w3.org/TR/CSP3/

## Учебная ML-модель

В разделе «Аудит политики» автоматически появляется ML-оценка для каждой политики. Классы: «Меньше признаков слабой CSP», «Нужна проверка настроек», «Выраженные признаки слабой CSP». Это дополнительная экспериментальная оценка: она не скрывает предупреждения обычного аудита. При расхождении выводится отдельное сообщение. Report-Only оценивается как конфигурация, но не блокирует нарушения.

Модель — настоящая многоклассовая логистическая регрессия: 23 признака, обученные коэффициенты и softmax. Во время применения модель получает признаки из текста CSP, а не результаты обычного аудита. Сервер читает сохранённые веса из ml/model.json один раз при запуске; внешние сервисы, API-ключи, Python и скачивание моделей не требуются. Пользовательские политики не сохраняются и не используются для обучения. При проверке URL сервер обращается к указанному сайту; вычисления ML остаются локальными.

Обучение воспроизводится командой `npm run train:ml` (или `node train-ml.mjs`). После переобучения перезапустите сервер. Генератор создаёт синтетические политики и получает метки от обычного аудитора. Следовательно, модель аппроксимирует наши правила и не открывает новые уязвимости независимо от них.

Данные: 952 уникальных вектора признаков, из них 571 для обучения, 190 для выбора версии по validation loss, 191 для тестирования. Между частями нет одинаковых векторов. Тестовое согласие с метками генератора — 90,6%; среди 80 примеров класса high 76 распознаны как high, 1 как review и 3 как lower. Это НЕ результат на реальных сайтах. Есть и ложные тревоги: полностью ограниченная политика с self/none может получить review. Не считайте прогноз гарантией безопасности и не игнорируйте обычный аудит.

Матрица ошибок (строки — метки генератора, столбцы — прогноз lower/review/high):

| Класс | lower | review | high |
|---|---:|---:|---:|
| lower | 28 | 3 | 0 |
| review | 0 | 69 | 11 |
| high | 3 | 1 | 76 |

`ml/dataset.jsonl` содержит примеры и принадлежность к выборкам, `ml/evaluation.json` — метрики и SHA-256 данных. Скрипт фиксирует seed и параметры обучения. Числа softmax — относительные баллы модели, не вероятность атаки. Показанные признаки — вклады коэффициентов в решение, не доказательства причинности.

Модель обучалась на default-src, script-src, style-src, img-src, connect-src, frame-ancestors, base-uri, form-action, object-src. Для неподдерживаемых директив (например script-src-elem), повторов и некоторых некорректных форматов она отказывается от оценки; обычный аудит остаётся доступен. Валидатор ML не является полным парсером CSP. Совместный эффект нескольких политик модель не оценивает.

## Проверка по ссылке

На первой вкладке вставьте адрес своего сайта и нажмите «Проверить сайт». Без схемы используется HTTPS. Проверяется одна конечная страница, без авторизации, cookies и обхода сайта. Показаны HTTP-статус, конечный URL, отсутствие CSP, Report-Only и результаты ML. При HTTP-ошибке заголовки могут принадлежать странице ошибки. HTML meta не извлекается. Отсутствующая CSP не передаётся ML как пустая политика.

Сетевые ограничения: стандартные порты 80/443, только публичные IP; из локальных разрешён сам анализатор на 127.0.0.1:8787 или localhost:8787. Проверка DNS на каждом перенаправлении с закреплением IP, тайм-аут проверки 25 секунд. Проверка HTTPS-сертификатов включена. Сервер не предназначен для публикации в интернете.

## React + Vite (требования части A)

Интерфейс перенесён на React + Vite. Главный файл: src/App.jsx. Компоненты с props: UrlForm, DirectiveCard, PolicyBuilder, TextForm, MLResult, AuditResults. Используются useState, useEffect, управляемые поля, валидация, map с key. Для fetch показаны loading/error/empty/success.

Установка: `npm install`. Сборка: `npm run build`. Запуск готовой сборки и API: `npm start`, затем http://127.0.0.1:8787. Для разработки сначала запустите API через `npm start`, затем в другом терминале `npm run dev`. Vite проксирует API на порт 8787.

Параметр base в vite.config.js задан как './'. Публичная публикация и минимум пять осмысленных коммитов пока НЕ выполнены. Для полной работы URL-проверки при публикации нужен backend; один GitHub Pages его не запускает. Сейчас проект работает локально. Секреты не используются и не сохраняются в localStorage.
